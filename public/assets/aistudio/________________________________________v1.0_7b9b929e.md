# 직원 스케줄 관리 및 프로젝트 참여 승인 시스템 설계 문서

| 항목 | 내용 |
|---|---|
| 문서 버전 | **v1.0 (확정본)** |
| 상태 | 기능과 업무 규칙은 사용자 결정으로 확정. 구현 세부 기본값은 부록 A에 [가정]으로 표시(개발 중 변경 가능) |
| 이전 버전 | v0.1 (AI 제안 초안) → v0.2 → v0.3 → v0.4 |
| 표기 규칙 | **[확정]** 사용자가 결정한 사항 / **[가정]** 확정 원칙에서 도출했거나 AI가 정한 구현 기본값 |

## 0. 확정 결정 사항 요약

| 구분 | 확정 내용 |
|---|---|
| 목적 | 직원들의 프로젝트 참여 일정 공유, 프로젝트 간 시간 겹침 확인, 허가권자 승인을 통한 참여 확정 |
| 규모 | 사용자 약 10명, 부서 2개 |
| 허가권자 | 부서장 2명(이하 A, B). 조직 규칙으로 지정 |
| 프로젝트 등록 | 허가권자만 등록. **자신이 등록한 프로젝트만** 수정·배정 |
| 참여 방식 | 허가권자가 직원을 배정 → 직원이 수락 또는 거절. 셀프 신청 없음 |
| 일반 직원 배정 승인 | 직원 수락 뒤 **허가권자 전원(배정한 허가권자 포함)이 각각 승인**. 순서 없음. 1명이라도 반려하면 전체 반려 |
| 허가권자 본인 투입 | 자기 프로젝트에 자신을 투입할 때 **누구의 승인도 필요 없음**. 다른 확정 프로젝트와 겹쳐도 **경고만 하고 허용** |
| 허가권자 간 배정 | A가 B를 A의 프로젝트에 배정하면 **B 수락**만으로 확정. 승인 없음 |
| 시간 겹침 | 비교 대상은 프로젝트 일정끼리만. 실제 시간이 겹치지 않으면 여러 프로젝트 동시 참여 가능. 겹치면 **경고와 함께 승인 차단** |
| 확정 후 일정 변경 | 다른 확정 프로젝트와 겹치게 되면 경고. 상대 프로젝트를 등록한 허가권자 승인 + 참여 직원 동의가 있어야 반영. 상대 프로젝트도 본인 등록이면 경고 확인 후 저장(직원 동의 불필요) |
| 개인 일정 | 관리하지 않음. 휴가 등 개인 사정은 직원이 배정을 거절해 처리 |
| 공개 범위 | 누가 어떤 프로젝트에 참여 중인지 전 직원에게 공개 |
| 로그인 | 시스템 관리자가 계정 발급, 이메일·비밀번호 로그인 |
| 외부 연동 | 없음(구글 로그인·캘린더 연동 삭제). 이메일 알림 발송만 사용 |
| 알림 | 인앱 알림 + 이메일 |
| 승인 대기 리마인드 | 없음 |
| 시스템 관리자 | 별도 역할 |
| 개발 형태 | 직접 개발 |

### 0.1 변경 이력 (v0.4 → v1.0)

| 항목 | v0.4 | v1.0 |
|---|---|---|
| 로그인 | 자체 계정 [가정] | 관리자 발급 계정, 이메일·비밀번호 로그인 [확정] |
| 일반 직원 배정 승인 | 배정하지 않은 허가권자(B)만 승인 [가정] | **A와 B 모두 승인**. 배정한 A도 승인 버튼을 다시 누름 [확정] |
| 허가권자 간 배정 | B 수락 [가정] | B 수락 필요, 승인 없음 [확정] |
| 허가권자 셀프 투입 시 겹침 | 미정 | 경고만 하고 허용 [확정] |
| 일정 변경 승인자 | 상대 프로젝트 등록 허가권자 [가정] | 상대 프로젝트 등록 허가권자 승인 + 참여 직원 동의 [확정] |
| 본인 프로젝트끼리 겹치는 일정 변경 | 경고 확인 후 저장 [가정] | 경고 확인 후 저장, 직원 동의 불필요 [확정] |

## 1. 개요

### 1.1 목적
- 직원들의 **프로젝트 참여 일정**을 한 곳에서 공유합니다.
- 허가권자가 직원을 배정할 때 **다른 확정 프로젝트와 시간이 겹치는지** 확인합니다.
- 일반 직원의 참여는 **직원 수락과 허가권자 전원의 승인**으로 확정됩니다.

### 1.2 범위
| 포함 | 제외 |
|---|---|
| 관리자 발급 계정, 이메일·비밀번호 로그인 | 구글 로그인·구글 캘린더 등 외부 캘린더 연동 |
| 허가권자의 프로젝트·프로젝트 일정 등록 | 개인 일정(휴가, 회의 등) 관리 |
| 직원 배정, 직원 수락·거절 | 직원 셀프 신청, PM 역할 |
| 허가권자 승인, 프로젝트 간 시간 겹침 차단 | 투입률(%) 관리 |
| 확정 후 일정 변경 시 겹침 경고, 승인·동의 | 승인 대기 리마인드 |
| 전사 프로젝트 캘린더, 참여 현황 공개 | 메신저 알림 |
| 인앱·이메일 알림, 감사 로그 | 모바일 네이티브 앱 (반응형 웹으로 대응) |

### 1.3 용어
| 용어 | 정의 |
|---|---|
| 허가권자 | 프로젝트를 등록하고, 자기 프로젝트에 직원을 배정하고, 참여와 일정 변경을 승인하는 사람. 현재 부서장 2명(A, B) |
| 프로젝트 일정(Session) | 참여자가 실제로 작업하는 날짜와 시간 블록. 반복 가능 (예: 매주 화·목 14:00~17:00) |
| 배정(Assignment) | 허가권자가 특정 직원을 자기 프로젝트에 넣는 것 |
| 셀프 투입 | 허가권자가 자기 프로젝트에 자기 자신을 넣는 것 |
| 시간 겹침 | 프로젝트 일정이 그 직원이 이미 확정된 다른 프로젝트 일정과 시간상 겹치는 것 |
| 허용된 겹침 | 셀프 투입 경고 확인 또는 일정 변경 승인으로 허용되어 이후 다시 막지 않는 겹침 |
| 일정 변경 요청 | 확정 참여자가 있는 프로젝트의 일정을 바꿀 때 승인·동의를 기다리는 변경 |

## 2. 사용자 역할

| 역할 | 주요 행위 |
|---|---|
| 직원 | 프로젝트 캘린더·참여 현황 조회, 배정 수락·거절, 일정 변경 동의·거절 |
| 허가권자 [확정] | 프로젝트 등록, 자기 프로젝트만 수정·배정, 셀프 투입, 일반 직원 배정 승인·반려(자기 프로젝트 포함), 일정 변경 요청 승인·반려 |
| 시스템 관리자 [확정: 별도 역할] | 계정 발급·비활성화, 부서·허가권자 지정, 감사 로그 조회. 프로젝트와 승인에는 관여하지 않음 [가정] |

> 허가권자도 직원으로서 프로젝트에 참여할 수 있습니다. 권한은 역할 기반 접근 제어(RBAC)로 처리합니다.

## 3. 기능 요구사항

### 3.1 계정과 로그인 [확정]
- **F-001** 시스템 관리자가 직원 계정(이메일, 이름, 부서, 역할)을 만듭니다.
- **F-002** 계정이 만들어지면 비밀번호 설정 링크가 담긴 초대 메일이 발송되고, 직원이 직접 비밀번호를 설정합니다. [가정]
- **F-003** 이메일과 비밀번호로 로그인합니다. 비밀번호는 Argon2id 등 느린 해시 함수로 저장합니다.
- **F-004** 비밀번호를 잊으면 이메일 링크로 재설정합니다. [가정]
- **F-005** 퇴사자는 관리자가 계정을 비활성화하고 기록은 보존합니다. [가정]

### 3.2 프로젝트 관리 (허가권자)
- **F-101** 프로젝트 등록: 이름, 설명, 기간, 필요 인원(선택). 허가권자만 등록합니다. [확정]
- **F-102** 프로젝트 일정 등록: 날짜와 시간 블록, 반복 규칙(iCalendar RFC 5545 RRULE)
- **F-103** 프로젝트 상태: `기획` → `인원 모집` → `진행` → `완료` / `취소`
- **F-104** 수정과 배정은 **등록한 허가권자만** 할 수 있습니다. [확정] 다른 허가권자는 조회와 승인만 합니다.

### 3.3 배정과 겹침 확인
- **F-201** 허가권자가 자기 프로젝트에 직원을 배정합니다. 셀프 신청은 없습니다. [확정]
- **F-202** 배정 화면에서 직원별 상태를 보여 줍니다.
  - 🟢 `겹침 없음`
  - 🔴 `프로젝트 시간 겹침`: 겹치는 프로젝트, 등록 허가권자, 시간대 표시
  - ⏳ `대기 중`: 다른 프로젝트 배정이 수락 또는 승인 대기 중 [확정]
- **F-203** 🔴 상태인 직원도 배정할 수는 있지만 경고를 띄우고, 확정 단계에서 막습니다. [가정]
- **F-204** 개인 일정은 확인하지 않습니다. 개인 사정이 있으면 직원이 배정을 거절합니다. [확정]

### 3.4 배정 유형별 처리

| 유형 | 직원 수락 | 허가권자 승인 | 다른 확정 프로젝트와 시간 겹침 |
|---|---|---|---|
| ① 허가권자가 자기 프로젝트에 **자신을 투입** | 불필요 | **불필요** [확정] | **경고만 하고 허용** [확정]. 허용된 겹침으로 기록 |
| ② 허가권자 A가 **다른 허가권자 B**를 A의 프로젝트에 배정 | **B 수락 필요** [확정] | **불필요** [확정] | 확정 차단 (일반 규칙 적용) [가정] |
| ③ 허가권자 A가 **일반 직원 X**를 A의 프로젝트에 배정 | **X 수락 필요** [확정] | **A와 B 모두 승인** [확정] | **경고와 함께 승인 차단** [확정] |

### 3.5 직원 수락·거절
- **F-301** 배정되면 대상자에게 인앱 알림과 이메일이 갑니다.
- **F-302** 대상자는 **수락 또는 거절**합니다. [확정] 거절 사유는 선택 입력입니다. [가정]
- **F-303** 수락 화면에도 시간 겹침 경고를 표시합니다.

### 3.6 일반 직원 배정 승인 (③) [확정]
- **F-401** 직원이 수락하면 **허가권자 전원**에게 승인 요청이 갑니다. 배정한 허가권자 A도 포함되어 승인 버튼을 다시 누릅니다.
- **F-402** 순서 없이 각자 결정합니다. **전원이 승인해야 확정**되고, **한 명이라도 반려하면 전체 반려**입니다.
- **F-403** 다른 확정 프로젝트와 시간이 겹치는 동안에는 **경고를 표시하고 승인 버튼을 막습니다.** 마지막 승인을 처리할 때 서버에서 다시 확인합니다. 반려는 언제든 할 수 있습니다.
- **F-404** 반려할 때는 사유를 반드시 입력합니다. [가정]
- **F-405** 확정되면 참여 현황과 전사 캘린더에 반영합니다.

### 3.7 확정 후 프로젝트 일정 변경 [확정]
허가권자 A가 자기 프로젝트 P의 일정을 바꾸면, P의 확정 참여자마다 다른 확정 프로젝트 Q와의 겹침을 다시 확인합니다.

| 겹침 상황 | 처리 |
|---|---|
| 겹침 없음 | 바로 저장하고 참여자에게 알림 [확정] |
| Q도 **A가 등록한 프로젝트** | 경고 확인 후 저장. **직원 동의 불필요** [확정] |
| Q가 **다른 허가권자 B가 등록한 프로젝트** | 일정 변경 요청 생성. **B 승인 + 해당 참여 직원 동의**가 모두 있어야 반영 [확정] |
| 겹치는 참여자가 **A 본인** | 경고 확인으로 처리 (셀프 투입 규칙과 동일하게 적용) [가정] |
| 여러 경우가 섞임 | 변경 요청 하나로 묶고, 필요한 승인과 동의를 모두 받아야 반영 [가정] |

- **F-501** 변경 요청이 승인·동의를 기다리는 동안에는 **기존 일정이 유지**됩니다.
- **F-502** B가 반려하거나 동의가 필요한 직원 중 1명이라도 거절하면 변경 전체가 반려되고 기존 일정이 유지됩니다. (전원 승인 원칙 적용) [가정]
- **F-503** 참여 직원이 B 본인이면 B의 결정 한 번으로 승인과 동의를 함께 처리합니다. [가정]
- **F-504** 반영된 겹침은 허용된 겹침으로 기록하고, 이후 다시 막지 않습니다.
- **F-505** 한 프로젝트에 대기 중인 일정 변경 요청은 한 번에 하나만 둡니다. [가정]
- **F-506** 변경으로 대기 중 배정과의 겹침이 생기면 해당 배정의 상태 표시를 갱신합니다.

### 3.8 프로젝트 일정 공유
- **F-601** 전사 프로젝트 캘린더: 월, 주, 타임라인(행 = 직원, 열 = 날짜) 보기. 대기 중인 배정은 구분 표시 [가정]
- **F-602** 참여 현황표: 직원 × 프로젝트. **전 직원에게 공개** [확정]
- **F-603** 필터: 부서(2개), 직원, 프로젝트

### 3.9 알림 [확정: 인앱 + 이메일]
- **F-701** 알림 대상: 배정됨, 수락·거절, 승인 요청, 승인·반려, 확정, 일정 변경, 일정 변경 요청(승인·동의 요청)과 결과, 참여 해제, 시간 겹침 경고
- **F-702** 승인 대기 리마인드는 보내지 않습니다. [확정]

### 3.10 대시보드
- **F-801** 직원: 내 프로젝트 일정, 수락 대기 배정, 동의 대기 일정 변경, 참여 중인 프로젝트
- **F-802** 허가권자: 승인 대기함(배정 승인, 일정 변경 승인), 내가 등록한 프로젝트와 인원 현황

## 5. 시간 겹침 확인 로직

### 5.1 원칙 [확정]
- 비교 대상은 **프로젝트 일정끼리만**입니다.
- 두 구간은 `A.시작 < B.종료` 이고 `B.시작 < A.종료` 일 때 겹칩니다. 끝나는 시각과 시작 시각이 같으면 겹치지 않습니다.
- 반복 일정은 프로젝트 기간 안에서 개별 일정으로 펼친 뒤 비교합니다.
- 실제 시간이 겹치지 않으면 여러 프로젝트에 동시에 참여할 수 있습니다.

### 5.2 의사코드
```
function checkOverlap(employee, sessions, excludeProjectId):
    target    = expand(sessions)
    confirmed = expand(sessions of projects where employee is APPROVED, project != excludeProjectId)
    conflicts = [(t, c) for t in target for c in confirmed
                 if t.start < c.end and c.start < t.end and not isAllowedOverlap(employee, t, c)]
    pending   = assignments of employee in [EMPLOYEE_PENDING, APPROVAL_PENDING], project != excludeProjectId
    결과 = { hasConflict: len(conflicts) > 0, conflicts, pending: len(pending) > 0 }

function canConfirmAssignment(a):
    r = checkOverlap(a.employee, a.project.sessions, a.project.id)
    if not r.hasConflict: 확정 허용
    else if a.type == SELF: 경고 확인 시 확정, 허용된 겹침으로 기록
    else: 확정 차단

function planSessionChange(project, newSessions, changer):
    approvers = {}; consents = {}; warnings = []
    for p in confirmedParticipants(project):
        for (t, c) in checkOverlap(p, newSessions, project.id).conflicts:
            owner = c.project.created_by
            if owner == changer or p == changer:
                warnings.append((p, t, c))          // 경고만
            else:
                approvers.add(owner); consents.add(p)
    if approvers 비어 있음: 경고 확인 후 즉시 저장 (겹침은 허용된 겹침으로 기록)
    else: 일정 변경 요청 생성 (approvers 승인 + consents 동의 필요)
```

## 6. 워크플로

### 6.1 배정 상태 전이
```
 ① 셀프 투입 ─────────────────────────────────────────────────▶ [APPROVED]  (겹침 시 경고 확인 후)
 ② 허가권자 → 다른 허가권자 ──▶ [EMPLOYEE_PENDING] ──수락──────▶ [APPROVED]
 ③ 허가권자 → 일반 직원    ──▶ [EMPLOYEE_PENDING] ──수락──▶ [APPROVAL_PENDING] ──허가권자 전원 승인──▶ [APPROVED]
                                       │ 거절                        │ 1명이라도 반려
                                       ▼                             ▼
                                  [DECLINED]                    [REJECTED]

 확정 전 어느 단계에서든 등록한 허가권자가 배정 취소 ──▶ [WITHDRAWN]
 [APPROVED] ── 프로젝트 취소 또는 등록한 허가권자의 참여 해제 ──▶ [RELEASED]
 ②·③의 [APPROVED] 전이 직전에 시간 겹침을 다시 확인하고, 겹치면 전이를 막음
```

### 6.2 일정 변경 요청 상태 전이
```
 일정 수정 ──겹침 없음 또는 경고만 해당──▶ 즉시 반영
     │
     └──승인·동의 필요──▶ [CHANGE_PENDING] ──필요한 승인·동의 모두 완료──▶ [CHANGE_APPROVED] (반영)
                               │ 반려 또는 거절 1건
                               ▼
                         [CHANGE_REJECTED] (기존 일정 유지)
 변경한 허가권자가 완료 전에 취소 ──▶ [CHANGE_WITHDRAWN]
```

### 6.3 규칙
1. ③의 승인 대상은 직원이 수락한 시점의 허가권자 전원입니다. 이후 허가권자가 바뀌어도 진행 중인 배정에는 영향을 주지 않습니다. [가정]
2. 배정 취소와 참여 해제는 프로젝트를 등록한 허가권자만 합니다. [가정]
3. 모든 상태 전이는 행위자, 시각, 사유와 함께 감사 로그에 기록합니다.

## 10. 화면 구성

1. **로그인**: 이메일·비밀번호, 비밀번호 재설정 링크
2. **홈 대시보드**: 내 프로젝트 일정, 처리할 항목 수, 참여 중인 프로젝트
3. **전사 프로젝트 캘린더**: 타임라인(행 = 직원, 열 = 날짜), 프로젝트별 색상, 대기 중 배정은 점선, 허용된 겹침은 표시 아이콘
4. **참여 현황표**: 직원 × 프로젝트
5. **프로젝트 목록·상세**: 본인 등록 프로젝트만 편집. 일정 저장 시 겹침 경고 창과 필요한 승인·동의 안내
6. **직원 배정** (허가권자): 직원 목록과 상태(🟢🔴⏳), 겹치는 프로젝트와 시간대, "나를 투입" 버튼
7. **처리함**: 수락 대기, 배정 승인 대기, 일정 변경 승인·동의 대기. 겹침 경고와 결정 현황(누가 승인했고 누가 남았는지)
8. **관리자**: 계정 발급·비활성화, 부서, 허가권자 지정, 감사 로그

## 12. 보안과 개인정보
- 다루는 개인정보는 이름, 이메일, 부서, 프로젝트 참여 정보입니다.
